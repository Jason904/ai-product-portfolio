TwitCanva

把割裂的 AI 图像 / 视频生成工具，变成一个可连续创作、可精细控制的多模态 AI 工作台。

核心判断：生成能力已经很强，真正缺的是能够承载完整创作流程的 Workflow，以及让用户获得稳定控制的中间层。

03 / PRODUCTIZE

UI Skill Lab

把“让 AI 写前端”从一次性的 Prompt 调试，变成一套有视觉目标、有规格合同、有验收门禁、有结构化修复的可复用 Workflow。

核心判断：AI Coding 的瓶颈已经不只是“能不能写 UI”，而是视觉意图没有形成 Agent 可以理解、执行、验收和修复的合同。

Method Productization
PRD → Visual Target → Visual Spec → Design System → Agent Build → Screenshot Acceptance → Diff Fix
Reference 占位

Visual-first

先让团队确认目标 UI，再让 Agent 开始实现，避免一开始就在错误视觉方向上高效编码。

Spec 占位

Visual → Spec

把视觉目标转成 tokens、layout、component tree 与 design rules，建立人类意图和 Agent 执行之间的中间协议。

验收占位

Product Quality Gate

区分“代码能运行”和“页面真的正确”，通过截图验收与规格检查守住 Product PASS。

Diff Fix 占位

Structured Diff Fix

把“再调好看一点”变成有证据、有位置、有优先级的结构化修复任务。

实践问题 → 方法抽象 Agent Contract / Spec 设计 AI Eval / Quality Gate Workflow / Skill 产品设计 开源与方法产品化

04 / VALIDATE

光帆 · AI 产品概念验证

用 AI 把一个还不存在的未来产品，提前变成老板和团队能够看见、理解、讨论和判断的产品体验。

核心判断：在高成本 Build 之前，先用 AI 做低成本 Experience Simulation，把原本开发完成以后才能发生的产品认知验证前移。

Decision Enablement
主场景视频 / 大视觉占位
后续替换为机场体验、产品视觉或概念视频
Concept → Product Visual → Scenario → Storyboard → Video → Shareable HTML → Stakeholder Decision

Technology → User Value

把 Camera、LLM、Watch、AIOS 等技术能力重新组织成用户能直接感知的“看见 → 理解 → 提醒 → 行动”。

Killer Scenario

用机场登机口变化的具体故事，而不是功能罗列，证明产品在什么时刻真正有存在价值。

Multimodal Visualization

用图片、Storyboard、视频和 HTML 承担不同层级的概念表达任务，降低理解和传播摩擦。

Shared Decision Object

让老板、产品、算法、硬件和设计围绕同一个“未来产品体验”讨论取舍、MVP 与是否继续投入。
